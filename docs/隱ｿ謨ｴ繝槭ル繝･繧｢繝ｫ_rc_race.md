# 調整マニュアル — rc_race.py 走行セッティング

対象: 教員・学生（セッティング実習）
前提: servo_test / throttle_test の学習が完了し、rc_race.py で走行できる状態

---

## 1. いちばん大事な考え方 —— 制御は「観測 × レバレッジ」

ハンドル制御は、次の2つの積み重ねでできています。

```
ハンドル = −( STEER_P_GAIN × 狙い[px]  +  STEER_D_GAIN × ズレの勢い[px/フレーム] )
              ─────────────  ────────     ─────────────  ──────────────────
              レバレッジ      観測          レバレッジ      観測
```

| | 観測（何を見るか） | レバレッジ（何倍で切るか） |
|---|---|---|
| **P** | 狙い [px] ＝ 下段帯の横ズレと上段帯のズレを SAKIYOMI の割合で混ぜた位置。SAKIYOMI=0（初期値）なら下段帯の横ズレそのもの ＝「いま、どれだけズレているか」 | STEER_P_GAIN |
| **D** | 横ズレの1フレームの変化量 [px/フレーム] ＝「ズレの勢い」＝「この先、どちらへズレていくか」 | STEER_D_GAIN |

- **Pは現在への反応**。ラインの中心へ引き戻す基本の力
- **Dは勢いへの先回り**。ラインへ近づく・離れる勢いを読んでカウンターを当て、Pの戻しすぎ（蛇行）を抑えるブレーキ役

> **なぜ「オレンジ線の傾き」をDに使わないのか（実走で得た教訓）**:
> 当初はD入力に傾き（上段と下段の差）を使う設計だったが、実走ログ3本の解析で
> 「傾き ≈ −0.15×横ズレ ＋ 0.013×横速度」という関係が判明。傾きは勢いよりも
> **現在のズレ自体と強く相関**するため（車がズレるとラインが斜めに見える幾何のせい）、
> 正のDゲインが「Pの打ち消し＋発散の助長」として働いてしまった。
> そこでD入力を横ズレの前フレーム差分（真の時間微分）に変更した。
> 傾きの表示は残してある（カメラ取付の確認・分析用）。

**レバレッジの鉄則**: 観測の質が良いほど強いレバレッジをかけられる。ノイズの多い観測に強いレバレッジをかけると、ノイズごと増幅されてハンドルが震える。ゲインを上げて震えが出たら、それは「観測の質の限界」に達した合図。

## 2. 調整ノブの3層構造 —— 順序を守ること

注視点（どこを見て運転するか）を変えるノブは3層あり、**上の層から順に決める**。逆にやると、ゲインを詰めた後に上の層を触って全部やり直しになる。

| 層 | ノブ | 動かすもの | 誰の領分 |
|---|---|---|---|
| 1 | カメラの取付角・高さ | **PとD両方の注視点を丸ごと** 前後させる | ハード整備 |
| 2 | 帯の高さ（ROI設定・共通設定） | 画面内での注視点の**配分**（Pをどこで、Dをどこで測るか） | 教員（共通設定） |
| 3 | STEER_P_GAIN / STEER_D_GAIN | それぞれの観測に対する**反応の強さ** | 学生（個別セッティング） |

```
調整の順序:  カメラ取付を決める → 帯を決める → ゲインを合わせる
（servo_testの「ハード優先、ソフトは最後の一押し」と同じ思想）
```

**上段帯の役割**: 傾きの表示（カメラ取付確認・走行分析）と、**先読み**（次の章）。
SAKIYOMI=0（初期値）のあいだは、上段帯は操舵には使われない。

## 2.5 先読み（SAKIYOMI）—— 上段帯を操舵に使う

### つづく線の検出

上段帯のズレは、「帯の中の白い物」ではなく「**下段帯のラインからつながっている線**」で決める。

1. 下段帯で、前のコマの位置に近い塊をラインとして選ぶ（追従ゲート。これまでどおり）
2. そこから上へ1行ずつ、**ひとつ下の行と横の位置が重なっている白い区間**だけをたどる
3. 上段帯の高さまでたどれたら、その位置が「遠くのズレ」。届かなければ、たどれた一番上の位置を使う

映像には、たどった線が小さな黄色い点の列で描かれる。ラインとつながっていない白い物（コース脇の物、床の反射、別の線）は、点が乗らないので遠くのズレに影響しない。線が横向きになる急カーブでは、横に長い区間の中央を最後の点としてたどり終える。

| パラメータ | 意味 |
|---|---|
| TADORI_NUKE | 線が途切れても飛び越えてたどる回数（初期値3。線のかすれが多いコースでは増やす） |
| TADORI_YOYU | 上下の行で横にずれていても「つながっている」とみなす幅（画面幅に対する割合） |
| TADORI_YOKO | 1行の中でこれより横に長い区間は、急カーブか線ではない物とみなしてたどり終える |

### 狙い

```
狙い = (1 − SAKIYOMI) × 下段帯の横ズレ ＋ SAKIYOMI × 上段帯のズレ
```

映像では白い縦線が「狙い」。P項はこの位置を画面中央へ持っていくようにハンドルを切る。実車の運転で「すぐ前の路面」ではなく「少し先」を見て走るのと同じ。

| SAKIYOMI | 走り方 |
|---|---|
| 0 | 下段帯だけを見る。直線では正確。カーブでは外へふくらみ、出口で行き過ぎやすい |
| 0.3〜0.5 | カーブの手前から切り始め、出口では早めに戻す。振動しにくい。カーブでは線の内側を通る |
| 1 | 上段帯だけを見る。大きく内側を回り、足元の線から離れる |

### 調整の手順

1. `SAKIYOMI` を 0.3 にし、`STEER_P_GAIN` を今の 0.8倍にする（上段帯のズレは下段帯より大きく出るため、そのままだと切りすぎる）
2. 走らせて、ログの「狙い」「横ズレ」「ハンドル」を見る
3. まだ振動する・出口で行き過ぎる → SAKIYOMI を 0.5 へ（P はさらに下げる。目安は元の 3分の2）
4. カーブで内側に入りすぎる（横ズレがカーブの外向きに大きく出る）→ SAKIYOMI を下げるか、上段帯を下へ動かして見る距離を近くする

**先読みを入れると D項はほとんど要らなくなる。** 先読み自体が「車の向き」を見ているので、行き過ぎを抑える役目を果たす。STEER_D_GAIN は 0〜0.015 に下げてよい。

> **傾きをD項に使って失敗した経緯との違い**: 1章の教訓は「傾きを*勢い*の代わりに使った」ことが原因。先読みは傾きを勢いとしてではなく、**見る位置を先へ移す**ために使う。車が線と平行にずれているとき、狙いは横ズレと同じ向きに（小さめに）出るので、P項を打ち消すことはない。

## 3. ゲイン調整の標準手順

1. **Pだけで始める**（STEER_D_GAIN = 0）。低速（ACCEL_SAIDAI は初期値の5のまま）で完走できるPを見つける
2. **速度を上げていく**。どこかで左右に振れ続ける「蛇行」が始まる
3. **蛇行が出たらDを足す**。0.02 から始めて少しずつ増やす（0.01〜0.05の範囲）。蛇行が収まるはず
4. **さらに速度を上げる** → 蛇行 → D（またはP）を微調整 → の繰り返し
5. Dを上げてハンドルが小刻みに震えだしたら上げすぎ。1〜2段階戻す

**症状と対処の早見表**

| 症状 | 原因の候補 | 対処 |
|---|---|---|
| ゆったり左右に蛇行 | Pが強すぎ or Dが足りない | Dを足す（0.01刻み）。ダメならPを1〜2割下げる |
| ズレてもなかなか戻らない | Pが弱い | Pを1〜2割上げる |
| ハンドルが小刻みに震える | Dが強すぎ（ノイズ増幅） | Dを下げる |
| 大きく外れたとき戻りきれない | Pが弱い or 切れ角不足 | Pを上げる。ダメならハード（アーム穴位置）を見直す |
| 発進直後だけ暴れる | 空転（発進が強すぎ） | ACCEL_HASSHIN を下げる / RAMPU を下げる |

**判断材料は走行ログ（logs/run_*.csv）**。「横ズレ」列をグラフにすると、蛇行は波形の振動として見える。振動の振幅と周期がゲイン調整の定量的な根拠になる。

## 4. アクセル（発進プロファイル）の調整

```
アクセル%
ACCEL_SAIDAI ┤            ┌──────────────
             │          ／
             │        ／   ← ACCEL_RAMPU（坂の急さ）
ACCEL_HASSHIN┤──────／
      0      ┼──┬─────────────→ 時間
              発進
```

### アクセル%の目盛り

アクセル%は、throttle_test で学習した点を基準にした目盛りです。

| アクセル | ESCへの信号 | 車の状態 |
|---|---|---|
| 0% | L点（モーターから音が鳴り始める点） | 動き出した車が回り続けられる、いちばん弱い信号 |
| 約8% | D点（タイヤが回り始める点） | 止まった状態から動き出せる信号。車ごとに少し違う |
| 100% | L点 ＋ 2.75% | モーター回転が頭打ちになる点 |

0〜約8%は「動き出せないが、回り続けられる」範囲です。ここを使うために、プログラムは発進から `KICK_BYO` 秒間だけD点の信号を出して動き出させ（**発進キック**）、そのあと設定したアクセルへ下げます。

**まずゆっくり走らせる。** ラインを追い切れないうちは、速度を上げても意味がありません。初期値の ACCEL_SAIDAI = 5 は、D点より弱い信号でのゆっくりした走りです。

| パラメータ | 意味 | 調整の考え方 |
|---|---|---|
| ACCEL_SAIDAI | 最高アクセル% | 初期値5。**途中で止まる車は1ずつ上げる**。完走できたら少しずつ上げる。上限も戦略で、攻めて100か、確実に走れる範囲に抑えるか |
| KICK_BYO | 発進キックの時間[秒] | 初期値0.3。動き出さない車は0.1ずつ長く。出だしが速すぎる車は短く |
| ACCEL_HASSHIN | 発進の瞬間の% | 空転しないギリギリまで上げるのが理想。グリップ（タイヤ・重量配置）次第。ACCEL_SAIDAI より大きくしても、ACCEL_SAIDAI で頭打ち |
| ACCEL_RAMPU | 踏み増し速度 %/秒 | 大きいほど早く全開。空転・蛇行が出たら下げる |

**走らせる前に、スタンドの上で確かめられます。** throttle_test の「▲ 微速前進」は、本番と同じキック→低速の信号（同じ `ACCEL_SAIDAI` と `KICK_BYO`）を出します。ACCEL_SAIDAI を変えたら、まずここで回り続けるかを見てから走らせると、止まる設定を事前に除けます。

**低速走行の注意**

- **ESCの電源は、rc_race.py を起動したあとに入れます。** ESCは電源を入れた瞬間の信号をニュートラルとして覚えるためです。順番が逆だったり、走行中にESCが再起動したりすると、L点・D点がずれて「急に速い」「動き出さない」になります。直すには、待機状態（N）でESCの電源を入れ直します

- 低いアクセルで走行中に止まると、プログラムは再発進しません（速度センサがないため、止まったことに気づけない）。止まる車は ACCEL_SAIDAI を上げます
- 床の上では、スタンドでタイヤを浮かせたときより力が要ります。throttle_test で回り続けた信号でも、走行では止まることがあります
- L点・D点はバッテリーの残量で動きます。減ってくると、同じ設定でも止まりやすくなります
- 起動時に「L点が未学習です」と表示される車は、アクセル0%＝D点で走ります。throttle_test の学習をやり直してください

発進の良し悪しは **ハードのグリップ** と表裏一体。バッテリー搭載位置（リア荷重）、タイヤの状態、路面の掃除——ソフトの数字だけでは決まらない。ここが「同じプログラムでもハードで差がつく」この競技の核心。

## 6. px と cm の関係（覚えておく）

カメラは遠近法で映すため、同じ100pxでも画面の高さによって実寸が違う。

- **下段帯（近く）**: 画面幅640px ≒ 実寸70〜80cm → **1px ≒ 1.1〜1.25mm**
- ゲート±100px ≒ **実寸±11〜13cm**
- 上段帯（遠く）は同じpxでもっと広い実寸（カメラ取付角に依存）

正確に知りたい場合は、床にメジャーを置いて camera_test で映し、帯の中で10cmが何pxかを数える（車ごとのpx→cm換算表が作れる。カメラ取付の個体差の数値化にもなる）。
