# 設計書 — rc_race.py（カメラ白線検出ドラッグレース）

対象: 自動車整備専門学校 3年生
前提知識: プログラミング経験・情報処理の知識は不要です
対応プログラム: rc_race.py 第1段階（カメラと画面表示のみ。車はまだ動きません）

---

## 1. この実習でいちばん大事なこと

この実習では、**全員がまったく同じプログラムを使います。**

それなのに、車ごとに走りは変わります。まっすぐ走る車もあれば、ふらふら蛇行する車、途中でコースアウトする車も出ます。

プログラムが同じなら、差が生まれる場所はひとつしかありません。**車、つまりハードウェアです。**

- カメラの取り付けがまっすぐか
- ホイールアライメントが合っているか
- ハンドル（サーボ）の中立位置が合っているか
- 重い荷物（ラズパイ・バッテリー）をどこに積むか
- サスペンションが路面の凹凸を吸収できているか

プログラムは、車がズレたぶんだけハンドルを切って修正します。つまり **修正が多い車＝整備が甘い車** です。修正の量は画面の数字と走行記録に残るので、ごまかせません。これは実際の自動運転車でも同じで、センサーの取り付けやアライメントの整備不良は、そのまま走りの乱れになって現れます。

**あなたの仕事は、プログラムを直すことではなく、修正がいらない車に仕上げることです。**

## 2. 自動運転のしくみ — 目・脳・手足

人間の運転を思い出してください。目で道を見て、脳で「少し右にズレてるな」と判断し、手でハンドルを戻します。この車もまったく同じ作りです。

```
   ┌──────────┐      ┌──────────┐      ┌────────────┐
   │  目       │      │  脳       │      │  手足       │
   │ カメラ    │ ──→ │ ラズパイ   │ ──→ │ サーボ・ESC │
   │ 白線を見る │      │ ズレを計算 │      │ ハンドル・   │
   │          │      │ 判断する   │      │ アクセル    │
   └──────────┘      └──────────┘      └────────────┘
        ↑                                     │
        └──────── 車が動くと見え方が変わる ←───┘
```

この「見る → 判断する → 動かす」を、1秒間に約20回繰り返しています。

部品の名前を整備士の言葉で言いかえると:

| プログラム上の呼び名 | 実際の部品 | 車でいうと |
|---|---|---|
| 目 | Pi カメラ | ドライバーの目 |
| 脳 | Raspberry Pi（小型コンピュータ） | ドライバーの頭脳 |
| 手 | ステアリングサーボ | ハンドルを回す腕 |
| 足 | ESC（モーターの制御アンプ） | アクセルペダルとスロットルの間の電子制御 |

## 3. プログラムの4つの状態

このプログラムは、いつでも次の4つの状態のどれかにいます。ブラウザ画面のいちばん上に、いまの状態が色つきで表示されます。

| 状態 | 色 | 意味 | このときやること |
|---|---|---|---|
| IDLE | 青 | 待機中 | 車とカメラの調整（キャリブレーション） |
| ARMED | 黄 | スタート待ち | 車から手を離して待つ |
| RUNNING | 緑 | 走行中 | 見守る。危ないときは STOP |
| FINISHED | 紫 | ゴール後 | タイムと記録を確認する |

状態はこう変わります:

```
 IDLE ──[ARMボタン]──→ ARMED ──[緑シグナル点灯]──→ RUNNING ──→ FINISHED
   ↑                                                              │
   └───────────── STOPボタン（いつ押してもIDLEに戻る）←────────────┘
```

RUNNING が終わる（＝車が止まる）条件は3つあり、どれか1つでも起きたら止まります。

1. **ゴール**: ゴールライン（進行方向と直角の太い横線）を通過した
2. **ラインロスト**: 白線を見失った（コースアウトしたときなど）
3. **タイムアウト**: 最大走行時間（15秒）を超えた — 安全装置です

## 4. プログラムの地図

rc_race.py の中身は7つのブロックに分かれています。**読むのはブロック1〜3だけで大丈夫です。**

| ブロック | 名前 | 内容 | 読む? |
|---|---|---|---|
| 1 | 設定 | 調整できる数値の一覧 | ◎ 触る場所 |
| 2 | 目 | 白線・シグナル・ゴールの見つけ方 | ○ 仕組みが分かる |
| 3 | 脳 | スタート・走行・停止の判断 | ○ 仕組みが分かる |
| 4 | 手足 | ハンドル・アクセルへの出力（第2段階で入る） | △ |
| 5 | カメラ | カメラの起動と撮影 | 読まなくてよい |
| 6 | 画面 | ブラウザへの映像配信と操作ボタン | 読まなくてよい |
| 7 | main | プログラムの入口 | 読まなくてよい |

ブロック5〜7は「Wi-Fiで映像を送る」「ボタンを受け付ける」といった裏方の仕組みで、車の走り方には関係ありません。

## 5. カメラはどうやって白線を「見て」いるのか

コンピュータにとって、写真は **数字が並んだ表** です。画像の1点1点（画素）に、明るさが 0（真っ黒）〜255（真っ白）の数字で入っています。

白線を見つける手順は、たったこれだけです。

**手順1: ラインの色のところだけ残す（二値化）**
この実習では **黒いライン** を使います。「80 より暗い画素はライン、それ以外は床」と決めて、画像をライン（白で表示）とそれ以外（黒）だけにします。この「80」がブロック1の `KURO_SHIKII`（黒のしきい値）です。ラインを見つけられないときはこの数字を上げ、床の影まで拾ってしまうときは下げます。

なぜ白線ではなく黒線なのか？　実習場の床はピカピカに磨かれていて、照明や窓の光を鏡のように映します。その映り込みはカメラには「真っ白」に写るため、白線を置いても映り込みのほうが明るく、区別できません。逆に黒線なら、映り込みが明るいほどラインが目立ちます。**センサにとって都合のよい環境を選ぶのも、立派なエンジニアリングです**（設定 `LINE_IRO` を "shiro" にすると白線用にも切り替えられます）。

**手順2: 見る範囲をしぼる（ROI）**
画面全体を見ると、コース外の白い物（壁・靴・紙）までラインと誤解します。そこで、画面の中の **横長の帯2本だけ** を見ます。

- **近くの帯**（画面の下のほう・青色で表示）… 車のすぐ前。ハンドル修正のもとになる「横ズレ」をここで測る
- **遠くの帯**（画面の中ほど・水色で表示）… 少し先。ラインの「傾き」をここで測る。位置は「帯の中の白い物」ではなく、近くの帯のラインから上へ **つながっている線をたどって** 決める（映像の小さな黄色い点の列）。先読み（SAKIYOMI）を使うと、ハンドルの計算にも使われる

**手順3: 白い点の平均位置を出す**
帯の中の白い点すべての位置を平均すると、線の中心が1点に決まります。その点が **画面の中央から何ピクセル（px）ズレているか** が「横ズレ」です。右にズレていればプラス、左ならマイナス。

**ゴールラインの見分け方（左右ゾーン方式）**: ふつうの縦線は画面の中央付近にしか写りません。ゴールの横線（幅1m）は画面の端から端まで横切ります。そこで「近くの帯（青）」の左端と右端に判定ゾーン（白い縦枠。検出すると赤くなる）を置き、**左右の両方** にラインの色が入ったときだけゴールと判定します。片側だけ黒くなっても（斜めに進入した瞬間や大きな影など）ゴールにはなりません。判定を「近くの帯」で行うのは、ゴールは車が横線を踏む直前に判定するものだからです。

**緑シグナルの見分け方**: 画面上部の枠（黄色で表示）の中で、緑色の面積が15%を超えたら「点灯」。1回だけの検出では発進せず、**3回連続で見えたときだけ** スタートします。カメラの一瞬のノイズでフライングしないためです。

## 6. 画面の数字はハードウェアの状態を映す鏡

ここがこの実習の核心です。ブラウザ画面の数字は、そのまま車の整備状態を表します。

### IDLE（止まっている状態）で分かること

車をスタート位置に置き、ライン上にまっすぐセットします。

| 画面の表示 | 正常 | ズレているとき疑う場所 |
|---|---|---|
| 横ズレ [px] | 0 に近い | 車の置き方が悪い／カメラが左右にズレて付いている |
| ライン傾き [°] | 0 に近い | 車が斜めに置かれている／カメラが回転して付いている |
| 十字マーク | ターゲットボードの中心 | カメラの高さ・上下向きがズレている |

**車をどんなに丁寧に置いても数字がゼロにならないなら、それはカメラの取り付けの問題です。** 車を置き直すのではなく、カメラを直します。これが「センサーキャリブレーション」です。

### RUNNING（走行中）で分かること

| 現象 | 疑う場所 |
|---|---|
| 横ズレがいつも同じ側に出て、ハンドルで戻され続ける | ホイールアライメント（トー）／サーボの中立位置 |
| 左右に振れ続ける（蛇行） | 修正が遅れて追いつかない。まずはアライメントで修正自体を減らす |
| 段差でズレが急に跳ねる | サスペンションが凹凸を吸収できていない／重量物の積み方 |
| ときどき「ライン NG」が点滅する | カメラのブレ（取り付け剛性）／照明の反射 |

実習の床は完全な平面ではありません。速度を上げるほど凹凸の影響は大きくなります。ラズパイやモバイルバッテリーは重い部品です。**どの高さに・前後どの位置に積むか** で、跳ねかたと接地が変わります。重心が高い・偏っている車は、数字が暴れます。

### 記録（CSV）に残るもの

走行のたびに、時間・横ズレ・傾きなどが毎コマ `logs` フォルダに自動保存されます。タイムだけでなく「どれだけ修正せずに走れたか」を採点に使います。走りの良し悪しは、感覚ではなく数字で比べます。

## 7. 設定パラメータ早見表（ブロック1）

★印だけが授業で触る可能性のあるものです。

| 名前 | 初期値 | 意味 | いつ変える |
|---|---|---|---|
| ★ CAM_HFLIP / CAM_VFLIP | False | 映像の左右・上下反転 | 映像が逆さまのとき |
| LINE_IRO | "kuro" | ラインの色（黒/白） | 会場の床に合わせて先生が指定 |
| ★ KURO_SHIKII | 80 | 黒と判定する暗さ | ラインを拾わない→上げる、影まで拾う→下げる |
| ★ SIG_WARIAI | 0.15 | シグナル点灯と判定する緑の割合 | シグナルに反応しない→下げる |
| ★ SAIDAI_SOKO_BYO | 15.0 | 最大走行時間［秒］ | コース長に合わせて先生が指定 |
| ★ HAISHIN_FPS | 10 | 映像配信のコマ数 | Wi-Fiが重いとき下げる |
| ROI_〜 | — | 検出に使う帯の位置 | 変えない（先生の指示があるときのみ） |
| GOAL_〜 / ROSUTO_〜 | — | ゴール・停止の判定条件 | 変えない |

## 8. 用語集

| 用語 | 意味 |
|---|---|
| Raspberry Pi（ラズパイ） | 手のひらサイズの小型コンピュータ。この車の「脳」 |
| ESC | Electronic Speed Controller。モーターの回転を制御するアンプ。ラズパイからの信号でアクセルの役割をする |
| サーボ | 信号で指定した角度まで回るモーター。ハンドルを切る「腕」 |
| PWM | 電気信号のパルスの幅で「どれだけ切るか・踏むか」を伝える方式。ラズパイが受信機の代わりにこの信号を作る |
| 画素（ピクセル、px） | 画像を構成する1つ1つの点。「横ズレ 12px」＝画像上で12点ぶんのズレ |
| 二値化 | 画像を白と黒の2色だけにする処理。白線だけを浮かび上がらせる |
| ROI | Region of Interest（注目エリア）。画像の中で検出に使う範囲 |
| キャリブレーション | センサーの取り付けや基準値を正しく合わせる作業 |
| fps | 1秒あたりの処理コマ数。多いほど細かく修正できる |
| CSV | 表形式のデータファイル。Excelやスプレッドシートで開ける |

## 9. 安全上の注意

- 第1段階のプログラムでは車は動きませんが、第2段階からは **プログラムが勝手に車を走らせます**。ARMボタンを押したら車に触らないこと
- 走行前は必ず進行方向に人がいないことを確認する
- 危ないと思ったら、ためらわず STOP ボタン。それでも止まらないときはターミナルで Ctrl+C
- バッテリーを繋ぐ順番・外す順番は「発進と停止のマニュアル」に従うこと

## 10. こんなときは（かんたんトラブル対応）

| 症状 | 確認すること |
|---|---|
| ブラウザで画面が開かない | クロームブックが実習用Wi-Fiに繋がっているか。URLの車番号が自分の車か |
| 映像が真っ暗 | カメラのケーブルの差し込み。レンズのキャップ |
| 映像が逆さま | 設定の CAM_HFLIP / CAM_VFLIP |
| ラインが「NG」のまま | ラインが青い帯の中に入っているか。KURO_SHIKII を上げてみる |
| シグナルに反応しない | シグナル画面が黄色い枠の中に映っているか。画面の明るさを最大に |

詳しくは各マニュアル（カメラ接続テスト・パラメータ調整 など）を参照してください。
